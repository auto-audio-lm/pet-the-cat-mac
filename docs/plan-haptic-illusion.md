# 계획: 햅틱 일루전으로 "고양이 털" 촉감 개선

- 상태: 계획만 작성. 구현은 아직 하지 않음.
- 기준 버전: v0.2.0 (main `89c2c4d`)

## 1. 배경: 사용자 피드백 (v0.2.0, 실제 Mac)

- 기본 설정(Fur)의 강도는 충분히 강했다.
- 하지만 느낌은 **딸깍에 가까웠고, 고양이보다는 트랙패드 자체가 "드드르륵" 긁히는 느낌**이었다.
- 요청 사항: 햅틱 일루전을 써서 실제 고양이나 사물을 만지는 느낌에 가깝게 만들기.

## 2. 원인 분석

| 원인 | 현재 동작 | 왜 딸깍으로 느껴지나 |
|---|---|---|
| 펄스 간격 | 이동 거리 약 8pt마다 1회. 보통 속도에서 약 20~40ms 간격 | 손끝은 약 30ms보다 띄엄띄엄 오는 펄스를 하나하나 끊어진 클릭으로 느낀다. 그래서 고무 돌기를 긁는 "래칫" 느낌이 난다. |
| 펄스 세기 | 가장 약한 액추에이션 ID 1(진폭 19). 5번째마다 ID 5 | 가장 약한 단계도 트랙패드에서는 분명한 "툭"이다. 그 아래로 내리는 방법을 아직 쓰지 않았다. |
| 규칙성 | 간격 지터는 ±35%뿐이고, 세기는 5회 주기로 반복 | 일정한 리듬과 패턴은 기계처럼 느껴진다. |
| 방향과 질감 | 어느 방향으로 문질러도 같다 | 실제 털에서 가장 뚜렷한 단서인 결 방향과 줄무늬가 없다. |
| 다른 감각 | 소리, 화면, 진동이 따로 움직인다 | 감각끼리 맞지 않으면 일루전이 약해진다. |

## 3. 하드웨어 한계 (할 수 없는 것)

- Force Touch 트랙패드는 Taptic Engine 하나가 유리판을 **옆으로 짧게 미는** 구조다.
- 만들 수 없는 것: 표면 마찰 변화, 부드럽게 들어가는 감각(컴플라이언스), 온도, 털의 결 자체.
- 쓸 수 없는 일루전:
  - 여러 액추에이터가 필요한 것: cutaneous rabbit, phantom sensation
  - 임의 파형이 필요한 것: 비대칭 진동으로 당기는 힘을 느끼게 하는 방식
- 따라서 목표는 "실제와 같은 촉감"이 아니다. **딸깍과 래칫 느낌을 없애고, 털을 쓰는 듯한 연속적이고 부드러운 질감으로 지각되게 하는 것**이다.

## 4. 적용할 일루전과 설계

### A. 시간적 합산으로 펄스를 "녹이기" (앱, 최우선)

**원리**: 아주 약한 펄스를 촘촘하게 내면, 손끝이 개별 클릭이 아니라 이어진 미세한 떨림으로 지각한다. 털을 스칠 때의 사르륵하는 마찰감에 가장 가깝다.

**설계 (새 스타일 "Silky fur (experimental)")**

- 펄스 간격
  - 기준: 이동 중에 시간 기준 10~14ms, ±30% 지터
  - 속도: 느리면 성기게, 빠르면 촘촘하게. 거리 기반과 시간 기반을 섞는다.
  - 상한: 액추에이터 호출이 약 4ms 걸린다는 보고가 있어, 최소 8ms
- 세기: 현재보다 약하게
  - 1순위: `MTActuatorActuate`의 float 인자로 진폭(약 14~70 범위로 제한)과 길이(4~8ms)를 연속 조절한다. 출처는 yab `docs/haptics.md`이며 **검증되지 않았다**.
  - 2순위: flags로 Light 변형을 고른다(1=Light, 2=Medium, 4=Firm, 8=Silent). 이것도 같은 출처이며 **검증되지 않았다**.
  - 둘 다 안 되면: ID 1을 유지하되 일부 펄스를 건너뛰어 평균 에너지를 낮춘다.
- 엔벨로프: 스트로크 시작 약 80ms 동안 세기를 서서히 올리고, 멈출 때 약 120ms 동안 서서히 내린다. 시작과 끝의 "툭"을 없애기 위해서다.
- 안전장치
  - 대기열 상한 2개를 유지한다(밀리면 버림).
  - 앱이 비활성이면 멈춘다.
  - 액추에이터를 쓸 수 없으면 공개 API로 대체한다. 단, 이 모드에서는 일루전이 불가능하므로 지금처럼 성긴 간격을 쓴다.

### B. 규칙성 제거와 털 결·줄무늬 (앱과 웹)

**원리**: 무작위성은 "자연물"로, 방향에 따른 차이는 "결"로 지각된다.

- 확률적 타이밍: 고정 간격 대신 지수분포 비슷한 무작위 간격을 쓴다. 털 한 올 한 올이 불규칙하게 걸리는 느낌을 낸다.
- 세기 무작위화: 펄스마다 ±20% 범위에서 흔든다(float 인자를 쓸 수 있을 때).
- 결 방향
  - 고양이 이미지는 위에서 본 모습이고 머리가 왼쪽에 있다. 기본 결은 머리에서 꼬리 쪽이다.
  - 정방향(결대로)으로 쓸면 성기고 약하게, 역방향은 촘촘하고 한 단계 강하게 한다.
  - 계산 방법: 1차로 마스크의 주축으로 결 방향을 구하고, 2차로 위치별 방향장을 만든다.
- 줄무늬(질감 맵)
  - 포인터 경로에서 털 이미지의 밝기 경계(줄무늬)를 지날 때 약간 강한 펄스를 넣는다.
  - 페이지가 픽셀 데이터를 갖고 있으므로 웹에서 계산해 앱에 보낸다.
- 메시지 확장 (하위 호환)
  - `{kind: "zone", zone, grain: <결 방향 라디안>}`
  - `{kind: "ridge", strength: 0..1}`
  - 옛 앱은 모르는 필드와 kind를 무시하므로 영향이 없다. 실제로는 `tick`으로 처리되므로, `ridge`는 앱이 `petTheCatNative.texture >= 2`를 알릴 때만 보낸다.

### C. 청각-촉각 일루전 (웹)

**원리**: 양피지 피부 착각(parchment-skin illusion). 문지르는 소리의 고음을 줄이면 같은 촉감도 더 부드럽고 매끄럽게 지각된다.

- 털 스치는 소리
  - 고음을 줄인다: lowpass 4.5kHz를 2.5~3kHz로.
  - 대역을 넓혀 더 "보송한" 노이즈로 만든다.
- 동기화: 펄스 타이밍에 맞춰 3~5ms 길이의 아주 작은 노이즈 알갱이를 섞는다. 소리와 촉감이 같은 사건으로 묶이게 하기 위해서다.
  - 클릭처럼 들리면 실패이므로, 기본은 꺼 두고 실험한다.
- 이번에 제거한 "가르랑 소리"는 다시 넣지 않는다.

### D. 시각적 pseudo-haptics (웹)

**원리**: 화면 속 커서의 움직임을 실제 손의 움직임과 조금 다르게 보여 주면, 뇌가 그 차이를 저항, 부드러움, 요철로 해석한다(Lécuyer의 pseudo-haptic texture).

- 손 커서
  - 털 위에서는 실제 포인터보다 살짝 늦게 따라오게 한다. 저역 필터 계수 약 0.75로 시작해 조정한다.
  - 역결 방향일 때는 더 늦게 따라오게 한다.
- 눌림 표현
  - 털 위에서 손을 약 3% 작게 그리고 그림자를 줄여, 털 속으로 묻히는 느낌을 준다.
  - Force Touch 압력이 있으면 그 값에 비례하게 한다.
- 털 흐트러짐 효과(sprinkle): 펄스와 같은 순간에 생기게 해서 촉감, 소리, 화면을 맞춘다.
- 주의: 포인터와 손이 너무 많이 어긋나면 조작감이 나빠진다. 지연 상한은 약 12px.

### E. 선택 기능: 촉각 가르랑

- 손을 고양이 위에 2초 이상 가만히 두면, 숨 쉬는 리듬(약 0.5Hz)으로 아주 약한 25Hz 펄스 묶음을 낸다.
- 소리 가르랑은 거슬린다는 피드백이 있었지만, 촉감은 다르게 느껴질 수 있다.
- 기본은 끄고 메뉴에서 켜게 한다. 배터리와 거슬림이 우려되므로 A~D를 평가한 뒤에 진행 여부를 정한다.

## 5. 구현 단계

| 단계 | 내용 | 위치 | 배포 |
|---|---|---|---|
| 1 | float 인자와 flags 동작 확인용 실험 메뉴(Compare Strengths 확장: 진폭과 길이 몇 단계) | 앱 | 빌드만 |
| 2 | Silky fur 스타일(A + B의 무작위화와 엔벨로프). 기본값을 지금보다 약하게 | 앱 | 빌드만 |
| 3 | 결 방향(마스크 주축)과 역결 강화 | 앱(방향은 이동 벡터로 계산) | 빌드만 |
| 4 | 줄무늬 `ridge`, 위치별 결 방향, 메시지 확장 | 웹 + 앱 | Cloudflare 배포 필요 |
| 5 | 청각 일루전 C와 시각 pseudo-haptics D | 웹 | Cloudflare 배포 필요 |
| 6 | (선택) 촉각 가르랑 E | 앱 | 빌드만 |

- 1~3단계는 앱만 다시 빌드하면 바로 느껴 볼 수 있다. 사용자 평가를 먼저 받기 위해 이 단계들을 우선한다.
- 각 단계는 별도 PR로 올린다. 웹 단계는 `docs/deploy-web.md` 절차로 배포한다.

## 6. 평가 방법

촉감은 자동 테스트로 판단할 수 없으므로 사용자 평가가 기준이다.

- 비교 대상: Haptics 메뉴의 Fur(v0.2.0), Silky fur, System clicks(classic)
- 진행 방법
  - 각 스타일로 등을 정방향 5회, 역방향 5회 문지른다.
  - 꼬리도 3회 문지른다.
  - 가능하면 어떤 스타일인지 모르는 상태로 비교한다.
- 평가 항목(1~5점)
  - 딸깍이나 래칫처럼 느껴지는 정도(낮을수록 좋음)
  - 털이나 천처럼 느껴지는 정도
  - 세기의 적절함
  - 결 방향 차이가 느껴지는지
  - 거슬림
- 자동으로 확인할 것
  - selftest: 펄스 스케줄의 간격 하한, 엔벨로프, 결 방향 판정, 대기열 상한
  - e2e: `ridge`, `grain` 메시지 전송, 옛 앱 호환
  - smoke test: 실행 확인

## 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| float 인자와 flags가 문서와 다르게 동작하거나 무시됨 | 1단계에서 먼저 확인한다. 안 되면 건너뛰기로 평균 에너지를 낮추는 방식만 쓴다. |
| 촘촘한 펄스가 "웅" 하는 버즈로 느껴짐 | 간격과 세기를 메뉴에서 조절할 수 있게 하고, 평가로 범위를 정한다. |
| 비공개 API가 macOS 업데이트로 바뀜 | 이미 있는 대체 경로(공개 API)를 유지하고, `available`과 `usable` 검사를 계속 쓴다. |
| 고빈도 펄스로 인한 배터리와 발열 | 이동 중에만 낸다. 대기열 상한을 유지하고, 유휴 상태에서는 0회. |
| pseudo-haptics 때문에 조작감이 나빠짐 | 지연 상한(약 12px)을 두고, 설정에서 끌 수 있게 한다. |
| 소리 알갱이가 클릭처럼 들림 | 기본은 끄고, 평가 후에 결정한다. |

## 8. 결정이 필요한 것

- 기본 스타일을 Silky fur로 바꿀지 여부. 평가 후에 정한다.
- 촉각 가르랑(E)을 진행할지 여부.
- 웹 단계(4, 5)의 배포 시점.
